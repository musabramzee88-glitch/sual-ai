# نشر «سُؤال AI» على خادم

الدليل لخادم VPS بنظام **Ubuntu 24.04** (أو 22.04) من أي شركة: Hetzner أو Contabo أو DigitalOcean أو غيرها. المواصفات المقترحة: ٤ گيگا رام على الأقل، ومعالجان، و٨٠ گيگا مساحة.

لا تضع أي كلمة مرور أو مفتاح في GitHub أو في المحادثات. كل الأسرار تبقى في ملف `.env` على الخادم فقط.

## ١. قبل التنصيب
1. **اشترِ النطاق** (مثل `sual-ai.com`).
2. **استأجر الخادم** باختيار Ubuntu 24.04. يصلك عنوان IP (مثل `203.0.113.10`) وكلمة مرور root، أو تضيف مفتاح SSH عند الإنشاء (أأمن).
3. **وجّه النطاق إلى الخادم**: من لوحة شركة النطاق، قسم DNS، أضف:
   - سجل `A` اسمه `@` وقيمته عنوان IP الخادم.
   - سجل `A` اسمه `www` وقيمته نفس العنوان.

   الانتشار ياخذ من دقائق إلى ساعات. تتأكد منه بالأمر `ping sual-ai.com`.

## ٢. التنصيب (أمر واحد)
من ويندوز: افتح PowerShell وادخل للخادم:
```
ssh root@203.0.113.10
```
ثم على الخادم:
```
curl -fsSL -o install.sh https://raw.githubusercontent.com/musabramzee88-glitch/sual-ai/claude/laughing-keller-wtmrzs/deploy/install.sh
```
إذا كان المستودع خاصاً ولم يعمل هذا الرابط، انسخ الملف `deploy/install.sh` من جهازك:
```
scp deploy\install.sh root@203.0.113.10:/root/
```
ثم شغّله:
```
sudo bash install.sh
```
السكربت يسأل عن:
- **النطاق.**
- **بريدك:** لشهادة HTTPS ولتنبيهات الأعطال.
- **مفتاح GitHub:** يطبع مفتاحاً، تضيفه في GitHub من المستودع ← Settings ← Deploy keys ← Add deploy key، **بدون** تفعيل Allow write access، ثم ترجع وتضغط Enter.
- **في النهاية، هل تُغلق الدخول بكلمة مرور:** وافق فقط إذا كنت تدخل بمفتاح SSH.

يأخذ تقريباً ١٠–٢٠ دقيقة، وأغلبها بناء الموقع.

## ٣. بعد التنصيب (مرة واحدة)
1. **املأ المفاتيح** في `.env`: مفتاح Gemini، وإعدادات البريد، ومعلومات التواصل:
   ```
   sudo nano /opt/sual-ai/.env
   ```
   ثم أعد تشغيل الموقع:
   ```
   sudo systemctl restart sual
   ```
2. **أنشئ حساب المدير:**
   ```
   sudo -u sual -H bash -c 'cd /opt/sual-ai && npm run admin:create'
   ```

## ٤. نقل البيانات من جهازك
1. **على جهازك** (داخل مجلد المشروع):
   ```
   npm run backup
   ```
2. **ارفع مجلد النسخة إلى الخادم** من PowerShell:
   ```
   scp -r backups root@203.0.113.10:/root/sual-import
   ```
3. **على الخادم:**
   ```
   sudo bash /opt/sual-ai/deploy/import.sh /root/sual-import
   ```
   ينقل قاعدة البيانات (المناهج والكتب والامتحانات والحسابات) وملفات الكتب والصور. وقبل الاستبدال يأخذ نسخة أمان من بيانات الخادم.

## ٥. نسخة احتياطية خارج الخادم (موصى به)
النسخة اليومية تُحفظ على الخادم نفسه في `/var/backups/sual`. حتى تبقى بياناتك سليمة إذا تلف الخادم، أرسل نسخة لمكان ثاني، مثل Hetzner Storage Box أو Google Drive أو أي مكان يدعمه rclone:
1. أضف الوجهة باسم تختاره، مثل `storagebox`. كلمة مرورها تبقى على الخادم فقط:
   ```
   sudo -u sual -H rclone config
   ```
2. اكتب الوجهة في `.env`، مثلاً `OFFSITE_REMOTE=storagebox:sual`، ثم أعد التشغيل:
   ```
   sudo systemctl restart sual
   ```

بعدها تُرسل كل نسخة يومية تلقائياً. وإذا فشل الإرسال يظهر تحذير في «حالة النظام» ويصلك بريد.

## ٦. المراقبة
- **صفحة حالة النظام:** `/admin/status` داخل لوحة الإدارة.
- **بريد عند أي عطل:** يصل على `ALERT_EMAIL`. السيرفر يفحص كل ساعة، ولا يكرر نفس التنبيه أكثر من مرة باليوم.
- **إذا توقف الخادم كله:** ما يگدر يرسل تنبيه بنفسه. أضف مراقباً خارجياً مجانياً (مثل UptimeRobot) على الرابط `https://النطاق/api/v1/health`.

## أوامر مفيدة
**السجل المباشر:**
```
sudo journalctl -u sual -f
```
**إعادة تشغيل الموقع:**
```
sudo systemctl restart sual
```
**نسخة احتياطية الآن:**
```
sudo -u sual -H bash -c 'cd /opt/sual-ai && npm run backup'
```
**الاسترجاع من آخر نسخة:**
```
sudo systemctl stop sual
```
```
sudo -u sual -H bash -c 'cd /opt/sual-ai && npm run restore -- --yes'
```
```
sudo systemctl start sual
```

**التحديثات:** تنزل وحدها. السيرفر يسحب الفرع من GitHub كل دقيقة، ويبني النسخة الجديدة، ويبدّل لها بدون ما يتوقف الموقع.
