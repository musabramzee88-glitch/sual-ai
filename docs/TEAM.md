# العمل المشترك على «سُؤال AI»

## القاعدة
- **الكود** يتشاركه الاثنان عبر GitHub. كل واحد يشتغل على جهازه، ويرفع (push) ويسحب (pull) بدل ما ينقلون ملفات.
- **البيانات الحية** (المدرسون، الاشتراكات، الامتحانات) تبقى في مكان واحد: قاعدة بيانات **الخادم**. لا تُنسخ لجهاز أحد إلا للتجربة.
- **قاعدة البيانات على كل جهاز منفصلة** (localhost). ما تتحدث وحدها بين الجهازين، وهذا مقصود: ما نريد تجربة صديقك تفسد بياناتك.
- **تغيير شكل قاعدة البيانات** (جدول أو عمود جديد) يمر عبر ملف migration داخل `prisma/migrations`، فينزل مع الكود ويطبّقه كل جهاز بأمر واحد.

## الإعداد (مرة واحدة)
1. **المالك:** المستودع ← Settings ← Collaborators ← Add people ← اسم حساب صديقك على GitHub (صلاحية Write).
2. **الصديق:** يقبل الدعوة من بريده، ثم:
   ```
   git clone https://github.com/musabramzee88-glitch/sual-ai.git
   cd sual-ai
   git checkout main
   ```
3. يجهّز جهازه حسب `deploy/README.md` للخادم، أو حسب الخطوات المكتوبة لك في المحادثة لجهاز ويندوز (قاعدة بيانات محلية باسم `sual`، و`.env` بمفاتيحه الخاصة، ثم `npm install` و`npx prisma migrate deploy` و`npm run db:seed`).
4. **ملف `.env` لا يُرفع إلى GitHub أبداً.** كل واحد يضع مفاتيحه (Gemini وغيرها). المفاتيح تُرسل بشكل خاص (مدير كلمات مرور)، لا في واتساب ولا في المحادثات.

## طريقة الشغل اليومية
| الخطوة | الأمر |
|---|---|
| قبل ما تبدأ: خذ آخر تحديثات | `git pull` |
| ابدأ ميزة جديدة على فرع خاص | `git checkout -b feature/اسم-قصير` |
| احفظ شغلك | `git add -A` ثم `git commit -m "وصف قصير"` |
| ارفعه | `git push -u origin feature/اسم-قصير` |
| لما تخلص: افتح **Pull Request** على GitHub | الثاني يراجعه ثم يدمجه بـ `main` |
| بعد الدمج: كل واحد يسحبه | `git checkout main` ثم `git pull` |

- **لا يشتغل الاثنان على الفرع نفسه بنفس الوقت.** كل واحد فرعه.
- **اتفقوا شنو يشتغل كل واحد** حتى ما يعدّلون الملف نفسه (مثلاً: أنت الامتحانات والتصدير، وهو الإدارة والدفع).
- إذا طلع تعارض (conflict) عند الدمج، لا تحذف شي. خلّي Claude يحلّه، أو افتحوه سوا.
- قبل الدمج شغّلوا: `npm run typecheck && npm run lint && npm test`.

## تغيير قاعدة البيانات
- الذي يغيّر `prisma/schema.prisma` يسوي migration: `npm run db:migrate`، ويرفع الملف الجديد مع الكود.
- **الثاني بعد `git pull`** يشغّل: `npx prisma migrate deploy` حتى تتحدث قاعدته.
- لا تعدّلوا migration قديم نُشر. أي تعديل جديد = migration جديد.
- لا تسوون migration بنفس الوقت على فرعين مختلفين. اتفقوا من يسويها أولاً ويدمجها، والثاني يسحبها قبل ما يكمل.

## البيانات المشتركة (الكتب والمناهج)
الكتب المرفوعة والفصول تُحفظ في قاعدة البيانات وفي مجلد `storage` على جهاز كل واحد. حتى يكون عند صديقك نفس الشي:
1. **عندك:** `npm run backup` (ينشئ مجلد `backups`).
2. تنقلون المجلد له بأي طريقة (Google Drive أو غيره).
3. **عنده:** يضعه بمجلد `backups` داخل مشروعه ويشغّل `npm run restore -- --yes`.

هذا **ينسخ** البيانات مرة واحدة، مو مزامنة مستمرة. وأي شي يرفعه واحد منكم بعد ذلك ما يوصل للثاني إلا بنسخة جديدة. وحتى تكون البيانات مشتركة فعلاً بدون نقل يدوي، استعملوا خادماً تجريبياً واحداً (انظر أدناه).

## خادم تجريبي مشترك (موصى به بعد النشر)
بعد ما ينزل الموقع على الخادم، نسوي نسخة ثانية منه باسم فرعي مثل `test.النطاق`، بقاعدة بيانات منفصلة عن الحقيقية:
- **تعدّلان الكود على جهازيكما** وترفعانه، فيتحدث الخادم التجريبي وحده، وتشوفان التغيير نفسه.
- **البيانات واحدة** على الخادم التجريبي: ما أحد يرفع كتاباً مرتين.
- **بيانات المدرسين الحقيقية لا تنكشف** لأحد منكما.
- النسخة الحقيقية تتحدث فقط من `main` بعد المراجعة.

## أمان
- كل واحد بحساب GitHub الخاص به، ولا أحد يعطي الثاني كلمة سره.
- لا ترفعوا `.env`، ولا نسخ قاعدة البيانات، ولا كتباً مدرسية مأخوذة بحقوق ملكية.
- أي مفتاح انكشف بالخطأ (حتى بمحادثة): يُلغى فوراً ويُنشأ غيره.
